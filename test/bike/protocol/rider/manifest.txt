# Fixtures for consumers of the opt-in 'rider' message (docs/protocol.md "Capabilities").
# Each line: <file> <kind> [key=value ...]
#   kind   rider | no-ftp
#            rider  the consumer ends up with this rider and FTP
#            no-ftp the message carries no usable FTP: keep whatever FTP was already in use
#   keys   id, name (ASCII-cleaned, see below), ftpW (as sent), ftpClamped (what a consumer that
#          accepts 50..500 W holds, whole watts rounded half up), source
#          For consumers of the opt-in 'intensity' capability (docs/intensity.md), every rider line
#          also has:
#          intensity    the preset name to show (ASCII-cleaned like name), or 'none' when the
#                       message carries no usable 'intensity' block: then the consumer plays at ftpW
#          percent, effectiveFtpW  the block's values (only when intensity is not none)
#          playClamped  the FTP an intensity consumer that accepts 50..500 W plays at: effectiveFtpW
#                       clamped, or ftpClamped when intensity is none. ftpClamped stays the measured
#                       FTP, so a consumer without intensity support checks ftpClamped and is right.
#          A usable block is an object with a whole-number effectiveFtpW in 1..10000, a whole-number
#          percent in 50..150 and a non-empty string name; anything else in it is ignored. A no-ftp
#          line ignores the block entirely.
# Name cleaning for C-style consumers: JSON escapes are decoded (\u0041 -> A); a character above
# ASCII, raw UTF-8 or as a \uXXXX escape, becomes one '?'; the result is cut to 31 characters.
# Tokens never contain spaces, so a line splits on whitespace. A consumer checks the keys it knows.
