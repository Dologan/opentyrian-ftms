# Fixtures for consumers of the opt-in 'rider' message (docs/protocol.md "Capabilities").
# Each line: <file> <kind> [key=value ...]
#   kind   rider | no-ftp
#            rider  the consumer ends up with this rider and FTP
#            no-ftp the message carries no usable FTP: keep whatever FTP was already in use
#   keys   id, name (ASCII-cleaned, see below), ftpW (as sent), ftpClamped (what a consumer that
#          accepts 50..500 W holds, whole watts rounded half up), source
# Name cleaning for C-style consumers: JSON escapes are decoded (\u0041 -> A); a character above
# ASCII, raw UTF-8 or as a \uXXXX escape, becomes one '?'; the result is cut to 31 characters.
# Tokens never contain spaces, so a line splits on whitespace. A consumer checks the keys it knows.
