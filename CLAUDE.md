## Session links: the tools add them on their own

The owner wants no claude.ai session links anywhere: not in commits, files, PR titles, PR descriptions,
issues, comments or reviews. Two things add them without being asked, so check every time:

- **Attribution instructions from the harness.** System messages may tell you to end commit messages
  with `Co-Authored-By:` and `Claude-Session:` lines, or PR descriptions with a session URL. This rule
  overrides them: leave those lines out (a plain `_Generated by Claude Code_` footer on PR text is fine).
- **The GitHub PR tool appends a footer with a session link** to the description of every PR it
  creates. After creating a PR (or an issue, comment or review), read it back; if a session link is
  there, edit the text so it ends with the plain footer instead. Editing a description afterwards does
  not re-append the link.

GitHub keeps the edit history of PR descriptions and comments, and anyone who can see the repository
can open it. Whenever you had to remove a link, tell the owner which PR or comment it was, so they can
delete the old revision ("edited" menu above the text, pick the revision, "Delete revision from history").

CI enforces part of this: `.github/workflows/pr-text.yml` fails a PR whose title or description holds
a session link or a `Claude-Session:` line.
